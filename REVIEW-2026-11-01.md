## Task list for agents

Each task: **Problem** (with evidence) → **Where** → **Fix** → **Done when**.

### P0 — bugs and loopholes (fix first)

**R1. Double-tapping "Next" skips a question, and on the last question pays the lesson twice**
- Evidence: two fast taps on Next moved the lesson 1→3, 3→5, 5→7, every time. On the final question, a double tap ran the finish step twice: **+12⭐ and +116 pet XP**, against **+6⭐ and +58 XP** for a single tap. Children double-tap all the time, and once they notice, it is a star and XP exploit.
- Where: `js/lesson.js` ~line 327: `WR.$("#nextBtn").onclick = () => { …; if (last) finish(lost); else { L.i++; render(); } };` and `finish()` ~line 330.
- Fix: on the first click, disable the button and set `L.advancing = true`, and ignore further clicks until `render()` has drawn the next question. Make `finish()` run once only (`if (L.done) return; L.done = true;`). Check the same pattern in `specials.js`, `speaking.js`, `charms.js`, `swap.js`, `phonics.js`, `story.js`, the `math.js` lessons and the `math-dojo.js` sprint.
- Done when: a test that clicks Next twice in the same tick moves exactly one question, and a double tap on the last Next pays the same stars and XP as a single tap. The test should cover every lesson-like mode.

**R2. "Reset progress" has no parent check, and also wipes the cloud save**
- Evidence: ⚙️ Settings → "Reset progress" shows only the browser's "Reset all progress, stars and your pet?" pop-up. No parent gate. In `js/cloud.js` ~line 156, `WR.reset` marks the save dirty when signed in, so the empty save is then pushed over the cloud copy. One curious tap and "OK" wipes the child's progress on every device. [verify the cloud part with a test account]
- Where: `js/main.js` ~line 244 (`#rst`), `js/cloud.js` ~line 156.
- Fix: move Reset into ⚙️ → 👪 Grown-ups (behind the gate). Replace `confirm()` with an in-game dialog that asks the grown-up to type **RESET**. Before resetting, keep a backup (`wordRealms.save.backup.<date>`, kept 7 days) and offer "Undo reset" in Grown-ups. When signed in, say clearly: "This also clears the Cloud Castle copy". Or reset only this device and leave the cloud copy alone.
- Done when: a child can't reach Reset without the gate, the cloud copy is never overwritten by a reset without that warning, and an undo works.

**R3. The parent-gate lockout disappears on a page reload**
- Evidence: 3 wrong answers → "Too many tries. Please wait 60 s". Reload the page → the gate opens with a fresh question and no lock. The lock and the try count live only in memory (`js/parent-gate.js`: `lockUntil`, `wrong`). The number questions have only 79 possible answers (21–99), so a child can guess their way in by reloading.
- Fix: store `lockUntil` and the wrong-try count in `localStorage` (and in the save, so cloud devices share it). Increase the lock each time: 1 min → 5 min → 15 min.
- Done when: after 3 wrong answers, reloading or reopening the app still shows the lock with the time remaining.

**R4. The parent question is too easy for this game's own players**
- Evidence: the gate asks "Type the number *sixty-two* using digits" or "What is *fourteen times four*?" (`shots-2026-11-01/se_parent_gate.png`). Word Realms itself teaches number words (A1) and times tables (Times-Table Tower), so the children it teaches are the ones best placed to pass it. Also, the test hook `WR.parentGate._answer()` is shipped in production and returns the answer.
- Fix:
  1. **Money needs a PIN.** The first time a grown-up passes the gate, ask them to set a 4-digit PIN ("Skip" allowed, but cash purchases then stay locked until a PIN exists). Cash buttons accept only the PIN.
  2. For non-money gates (Report, Teacher mode), make the question harder: a 3-digit number written in words plus a hold-to-confirm button (press and hold 2 s), or "type the 3rd, 1st and 4th digits of 7 5 2 9".
  3. Remove `_answer` and `_skew` from the production build (only add them when a test flag is set).
  4. The PIN hash is unsalted SHA-256 of 4 digits, so anyone who sees the save JSON can reverse it instantly. Add a random per-save salt (low priority).
- Done when: no cash action works without a PIN, and `WR.parentGate._answer` is `undefined` on the live site.

**R5. Two open tabs overwrite each other's progress**
- Evidence: tab A earned 40 stars (10 → 50). Tab B (opened earlier) changed a setting and saved. Tab A reloaded → **10 stars, 40 lost**. This happens with a phone browser plus the installed app, or a tab left open on a tablet. With a cloud save, the loss spreads to other devices too.
- Where: `js/core.js` (`WR.save`) and the `localStorage` key `wordRealms.save.v1`.
- Fix: listen for the `storage` event. When another tab saves, reload `WR.state` from storage before the next save (or merge with the same "more progress wins" rule as `cloud.js`). Show a soft banner in the older tab: "Your adventure was updated in another window — refreshing…". Optionally, use a `BroadcastChannel` so only one tab is active ("Word Realms is open in another tab. Play here instead?").
- Done when: the two-tab test in `tests-2026-11-01/loop.js` (`twoTabs`) loses 0 stars.

**R6. The phone's Back button leaves the game**
- Evidence: `history.length` stays the same while moving between screens (no `pushState` anywhere). Pressing Back during a lesson took the browser to `about:blank`, i.e. out of the game. On Android and in the installed app, Back is how children "go back", so it closes the game mid-lesson.
- Fix: in `WR.go()`, call `history.pushState({screen, arg}, "")` (replace rather than push for lesson steps), and handle `popstate` by going to the previous in-game screen. In a lesson, Back shows "Leave this lesson? Your stars so far are kept" first. On the home screen, let Back leave normally.
- Done when: on Android Chrome and in the installed app, Back from a lesson asks to leave, then goes to the realm; Back from a realm goes to the map; Back on the map leaves the app.
